## 7. Standar Commit Message

Untuk menjaga histori commit tetap rapi dan mudah dipahami, commit message harus:
- ditulis dengan bahasa yang jelas,
- tidak disingkat (contoh: hindari "yg", "bgt", dan sejenisnya),
- singkat, padat, dan informatif.

Format:
`[Action] [What Changed]`

Contoh:
- Add team members to README
- Create team contract document
- Update project structure
- Fix typo in README
- Add initial Kotlin source file

Aturan:
- Gunakan kata kerja awal seperti Add, Update, Fix, Create, Remove.
- Commit message harus menjelaskan perubahan secara singkat dan jelas.
- Boleh menggunakan bahasa Indonesia atau bahasa Inggris secara konsisten.
- Hindari commit message yang terlalu umum seperti:
  - update
  - fix
  - done

## 8. Mekanisme Eskalasi

Jika tim mengalami kendala yang tidak dapat diselesaikan bersama, langkah eskalasi dilakukan sebagai berikut:

1. Diskusikan terlebih dahulu di grup tim.
2. Jika belum menemukan solusi, lakukan diskusi singkat saat kerja kelompok.
3. Jika masih deadlock/kebuntuan, ketua tim atau perwakilan anggota menghubungi asisten praktikum.
4. Jika diperlukan, masalah dikonsultasikan kepada dosen pengampu.

Mekanisme ini dibuat agar setiap masalah dapat diselesaikan dengan tertib dan tidak menghambat progres tugas.
